# 이뻐(IPPEO) JSON 리포트 연동 매뉴얼 — 메디힘 개발사용

작성일: 2026-06-28 · 대상: 메디힘 신규 개발사

---

## 1. 개요

기존에는 리포트를 **아이프레임(iframe)**으로 임베드해 제공했습니다.
이제 **개발(DEV) 환경에 한해**, 리포트 내용을 **JSON으로도 제공**합니다.
귀사는 이 JSON을 받아 **자체 디자인을 입혀 렌더링**하고, 필요 시 **내용을 수작업으로 수정**할 수 있습니다.

- 웹훅 통신 방식은 **기존과 동일**합니다. 변경 없습니다.
- 기존 `embed_url`(아이프레임)도 **그대로 유지**됩니다. JSON 연동 중 문제가 생기면 아이프레임으로 폴백 가능합니다.
- 운영(PROD) 환경은 현행 아이프레임 그대로이며, 본 JSON은 **DEV 콜백에만** 포함됩니다.

---

## 2. 받는 방법 — 웹훅 콜백의 `json_url`

리포트 생성이 끝나면 기존과 동일한 웹훅 콜백이 전송됩니다.
DEV 콜백에는 각 리포트 항목에 **`json_url` 필드가 추가**됩니다 (`embed_url`은 그대로 유지).

```jsonc
{
  "status": "report_ready",
  "consultation_id": "...",
  "ippeo_consultation_id": "...",
  "ippeo_consultation_round": 3,
  "customer_name": "田中様",

  "patient_report": {                       // 고객용 리포트 (R4)
    "report_token": "abc123",
    "embed_url": {                          // 기존 아이프레임 (유지)
      "ja": ".../embed/patient/ja/abc123",
      "ko": ".../embed/patient/ko/abc123"
    },
    "json_url": {                           // ★ 추가 — 이 URL을 GET 하세요
      "ja": ".../api/dev/report/ja/abc123.json",
      "ko": ".../api/dev/report/ko/abc123.json"
    }
  },

  "doctor_report": {                        // 병원용 리포트 (R3, 한국어)
    "report_token": "def456",
    "embed_url": { "ko": ".../embed/doctor/ko/def456" },
    "json_url":  { "ko": ".../api/dev/report/ko/def456.json" }
  }
}
```

- **`patient_report`** = 고객용 리포트(일본어 `ja` + 한국어 `ko`)
- **`doctor_report`** = 병원용 리포트(한국어 `ko`만)
- 원하는 언어의 `json_url`을 **GET** 하면 아래 형식의 JSON이 반환됩니다.
- 인증 헤더는 불필요합니다(토큰이 URL에 포함). 응답은 `application/json; charset=utf-8`.

### 엔드포인트 형식
```
GET /api/dev/report/{lang}/{token}.json     (lang = ja | ko)
```
- 404: 토큰에 해당하는 리포트 없음
- 403: 아직 열람 불가 상태
- 병원용(R3)은 한국어 전용입니다. `ja`로 요청해도 한국어 데이터가 반환됩니다.

## 3. JSON 구조

최상위는 `meta`(요약 정보)와 `blocks`(렌더링할 순서 있는 블록 배열)로 구성됩니다.

```jsonc
{
  "meta": {
    "이름": "田中様",
    "리포트종류": "고객용",      // "고객용"(R4) 또는 "병원용"(R3)
    "회차": 3,
    "역할라벨": null,            // 병원용일 때만: "상담실장" 또는 "의사". 고객용은 null
    "언어": "ja",
    "리포트제목": "田中様 鼻のご相談リポート",
    "날짜": "作成日：2026年6月28日"
  },
  "blocks": [
    { "구분": "큰제목", "내용": "..." },
    { "구분": "섹션제목", "섹션키": "section1_key_summary", "내용": "ご相談の要点" },
    { "구분": "리스트", "내용": ["...", "..."] }
  ]
}
```

### `blocks` — 위에서 아래 순서대로 렌더링

각 블록의 **`구분`** 값(6종)에 따라 디자인 컴포넌트를 매핑하면 됩니다.

| `구분` | 의미 | 필드 | 렌더링 권장 |
|--------|------|------|------------|
| `큰제목` | 리포트 최상단 제목 | `내용`(문자열) | H1 / 페이지 타이틀 |
| `섹션제목` | 소제목(섹션 헤더) | `내용`(문자열), `섹션키`(원본 식별자) | H2 / 섹션 구분선 |
| `본문` | 문단 텍스트 | `내용`(문자열) | `<p>` 문단 |
| `리스트` | 불릿 목록 | `내용`(문자열 배열) | `<ul><li>` |
| `항목` | 라벨-값 쌍 | `라벨`(문자열), `값`(문자열) | 정의형(라벨 : 값) / 표 행 |
| `주석` | 비고·면책·보충 | `내용`(문자열) | 작은 회색 텍스트 |

**규칙:**
- `구분`은 위 6종만 나옵니다. 그 외 값은 없습니다.
- 값이 빈 항목은 **애초에 블록으로 포함되지 않습니다**(빈 블록 방어 불필요).
- `섹션키`는 같은 섹션의 블록들을 묶고 싶을 때 사용하는 식별자입니다(렌더링에 필수 아님). 예: 한 `섹션제목` 이후 다음 `섹션제목` 전까지가 한 섹션입니다.

## 4. 렌더링 예시 (의사 코드)

```js
function renderReport(json) {
  const root = document.createElement("div");
  for (const block of json.blocks) {
    switch (block.구분) {
      case "큰제목":
        root.append(h("h1", block.내용)); break;
      case "섹션제목":
        root.append(h("h2", block.내용)); break;
      case "본문":
        root.append(h("p", block.내용)); break;
      case "리스트":
        root.append(h("ul", block.내용.map(t => h("li", t)))); break;
      case "항목":
        root.append(h("div", [h("dt", block.라벨), h("dd", block.값)])); break;
      case "주석":
        root.append(h("small", block.내용)); break;
    }
  }
  return root;
}
```

섹션 단위로 카드/박스를 그리고 싶다면, `구분 === "섹션제목"`을 만날 때마다 새 섹션 컨테이너를 시작하고 다음 `섹션제목` 전까지의 블록을 그 안에 넣으면 됩니다.

## 5. 실제 응답 샘플 (고객용 R4 / 일본어)

```json
{
  "meta": {
    "이름": "田中様", "리포트종류": "고객용", "회차": 3, "역할라벨": null,
    "언어": "ja", "리포트제목": "田中様 鼻のご相談リポート", "날짜": "作成日：2026年6月28日"
  },
  "blocks": [
    { "구분": "큰제목", "내용": "田中様 鼻のご相談リポート" },
    { "구분": "섹션제목", "섹션키": "section1_key_summary", "내용": "ご相談の要点" },
    { "구분": "리스트", "내용": ["鼻先が尖って見える", "自然な仕上がりを希望"] },
    { "구분": "섹션제목", "섹션키": "section2_cause_analysis", "내용": "原因・背景の分析" },
    { "구분": "본문", "내용": "原因の全体像です。" },
    { "구분": "리스트", "내용": ["原因1の説明", "原因2の説明"] },
    { "구분": "본문", "내용": "核心整理です。" },
    { "구분": "섹션제목", "섹션키": "section4_recovery", "내용": "回復について" },
    { "구분": "항목", "라벨": "1〜3日", "값": "腫れの時期" },
    { "구분": "항목", "라벨": "7日", "값": "抜糸の時期" },
    { "구분": "섹션제목", "섹션키": "section8_cost_estimate", "내용": "費用の目安" },
    { "구분": "리스트", "내용": ["鼻尖形成術: 約200〜400万ウォン（参考・税別）"] },
    { "구분": "주석", "내용": "正確な見積もりは診察後に。" }
  ]
}
```

> 위는 일부만 발췌한 예시입니다. 고객용(R4)은 최대 10개 섹션(핵심요약/원인분석/추천방향/회복/흉터/주의점/리스크/비용/내원일정/메시지)이 순서대로 옵니다.

---

## 6. 섹션 구성 참고

**고객용(R4)** — `섹션키` 순서:
`section1_key_summary`(핵심 요약) → `section2_cause_analysis`(원인 분석) → `section3_recommendation`(추천 방향) → `section4_recovery`(회복) → `section5_scar_info`(흉터) → `section6_precautions`(주의점) → `section7_risks`(리스크) → `section8_cost_estimate`(비용) → `section9_visit_date`(내원일정) → `section10_ippeo_message`(이뻐 메시지)

**병원용(R3, 한국어)** — `섹션키` 순서:
`section1_consultation_summary`(상담 요약) → `section2_procedure_plan`(시술 계획) → `section3_cost_estimate`(비용 견적) → `section4_scheduling`(일정) → `section5_considerations`(고려사항) → `section6_action_items`(액션 아이템) → `section7_voice_analysis`(음성 분석, 있을 때만)

## 7. 주의사항

1. **블록 순서를 그대로 유지**해 렌더링하세요. 의미 순서가 보장되어 있습니다.
2. **상담 내용에 따라 일부 섹션/블록이 없을 수 있습니다.** 항상 존재한다고 가정하지 마세요. (블록 배열을 순회하는 방식이면 자연히 처리됩니다.)
3. **언어**: 고객용은 `ja`/`ko` 모두, 병원용은 `ko`만 의미가 있습니다.
4. 본 JSON은 **DEV 환경 전용**입니다. 운영 반영은 메디힘 측 검증 후 별도 일정으로 진행됩니다.
5. 문의/이슈는 이뻐 AI팀(유범석)으로 전달해 주세요.
